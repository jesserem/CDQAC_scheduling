# CDQAC — Conservative Discrete Quantile Actor-Critic for (F)JSP

Official implementation of

> **Generalizing Beyond Suboptimality: Offline Reinforcement Learning Learns Effective Scheduling through Random Solutions**
> Jesse van Remmerden, Zaharah Bukhsh, Yingqian Zhang
> *Transactions on Machine Learning Research (TMLR), 2026*
> OpenReview: https://openreview.net/forum?id=4vVhm4817Q

CDQAC is an offline reinforcement learning method for the Job Shop Scheduling
Problem (JSP) and the Flexible Job Shop Scheduling Problem (FJSP). It learns
scheduling policies purely from static, suboptimal datasets — including data
generated by a uniformly random policy — and matches or outperforms strong
online RL baselines without any environment interaction during training.

The method combines:

- a **dueling quantile critic** over machine–operation pairs with separated
  value/advantage inputs (Eq. 6 in the paper),
- a **Conservative Q-Learning (CQL)** penalty on the expected return (Eq. 4),
- **delayed policy updates** (η = 4) to stabilize offline actor–critic learning,
- the Dual Attention Network (DAN) encoder from [Wang et al., 2023](https://doi.org/10.1109/TNNLS.2023.3306421).

## Installation

```bash
conda create -n cdqac python=3.11
conda activate cdqac
pip install -r requirements.txt
```

For a CUDA build of PyTorch, see the note in `requirements.txt`.

## Datasets

The packed training/evaluation datasets are hosted on the HuggingFace Hub:

```bash
python scripts/download_datasets.py          # FJSP datasets (./dataset)
python scripts/download_datasets.py --all    # + JSP datasets and raw GA trajectories
```

Each `.npy` training file holds one dict per instance with the instance
definition (`JobLength`, `OpPT`) and the trajectories of every data source:
PDR rules (`rules`), GA hall-of-fame/population (`ga`, `ga_pop`), random
rollouts (`random`), and ε-PDR rollouts (`eps_random_*`), stored as action
lists that are replayed through the environment at training time.

All datasets can also be regenerated from scratch:

```bash
# 1. Generate instances + PDR trajectories for all sizes/sources
python -m data_generation.generate_datasets

# 2. Append random trajectories
python -m data_generation.add_random_trajectories --path_file ./dataset/SD1_train_10_5_1000.npy --num_random 100

# 3. (Optional) epsilon-PDR trajectories (App. F.3)
python -m data_generation.add_eps_pdr_rules --path_file ./dataset/SD1_train_10_5_1000.npy --eps_random 0.1

# 4. (Optional) GA trajectories: run data_generation/run_GA_custom.py inside a
#    clone of the Job Shop Scheduling Benchmark repo (see the file's docstring),
#    then merge the resulting JSONs:
python -m data_generation.add_ga_data --dataset ./dataset/SD1_train_10_5_1000.npy --ga_folder ./GA_data/10_5
```

## Training

Train CDQAC on the Random dataset (the paper's default setting):

```bash
python train_cdqac.py --train_instance SD1_train_10_5_1000.npy --eval_instance SD1_10_5_val.npy \
    --use_random True --n_random 100 --num_instances 500 --seed 1
```

Dataset sources are selected with `--use_dispatching` (PDR), `--use_ga_hof` /
`--use_ga_pop` (GA), `--use_random`, and `--use_eps_pdr`; any combination can
be enabled. All hyperparameters (defaults = Table 11 of the paper) live in
`cdqac/configs/cdqac_config.py` and can be overridden on the command line.
Checkpoints and a `config.yml` are written to `--save_folder`.

Baselines from the paper are trained the same way:

| Script | Method |
|---|---|
| `train_cdqac.py` | CDQAC (ours) |
| `train_bc.py` | Behavioral Cloning |
| `train_iql.py` | Implicit Q-Learning |
| `train_dmsac.py` | Offline-LD (discrete maskable SAC) |
| `train_mqrdqn.py` | Offline-LD (maskable QR-DQN) |
| `train_td3_awr.py` | TD3-AWR |

Ablations (Sect. 5.5) are switches on the CDQAC config: `--use_cql False`,
`--use_qrdqn False`, `--use_adv_net False`, `--update_freq_policy 1`, and the
dataset-property ablations `--use_proxy_reward`, `--use_sparse_reward`,
`--cutt_off_episode_prob 0.1` (Table 3).

The exact argument lines used for every experiment in the paper are preserved
in `experiments/*.txt` (one run per line). `slurm/train_array.sbatch` shows
how to submit them as a SLURM array job.

Weights & Biases logging is optional: add `--use_wandb True` (requires
`wandb` to be installed and configured).

## Evaluation

Evaluate a trained checkpoint folder (greedy + 100-sample evaluation, as in
the paper) on the Brandimarte/Hurink benchmarks and generated instances:

```bash
python -m evaluation.evaluate_fjsp --model_path checkpoints/<run_folder>
python -m evaluation.evaluate_fjsp_large --model_path checkpoints/<run_folder>   # 30x10 / 40x10 generalization
python -m evaluation.evaluate_jsp --model_path checkpoints/<run_folder>          # Taillard / Demirkol JSP
```

Other reference points:

```bash
python -m evaluation.eval_dispatching       # PDR baselines
python -m evaluation.eval_random            # random policy baseline
python -m evaluation.ortools_solver         # CP-SAT (OR-Tools) reference solutions
python -m evaluation.summarize_gaps         # aggregate result folders into per-experiment tables
```

## Analysis (Sect. 5.2, App. F & K)

`analysis/` contains the scripts behind the dataset-property study and the
critic diagnostics; each is documented in its header and takes a trained
checkpoint / dataset path as argument:

- `coverage_action_prefix.py` — state–action coverage (SACo, Table 2)
- `trajectory_quality_return.py` — trajectory quality (TQ, Table 2)
- `density_embedding_knn.py` — embedding-space k-NN density proxy (Table 2)
- `quantile_distribution_experiment.py`, `critic_diagnostics.py`,
  `cql_effect_experiment.py` — quantile critic diagnostics (App. K)
- `notebooks/` — notebooks used to produce the tables and figures

## Repository layout

```
cdqac/            algorithm package (methods, DAN networks, replay buffer, configs)
env/              FJSP/JSP simulation environments and instance utilities (from DANIEL)
data/             benchmark instances (Brandimarte, Hurink, Taillard, Demirkol) + reference solutions
data_generation/  dataset construction (PDR, GA, random, eps-PDR, JSP)
evaluation/       evaluation on benchmark + generated sets, heuristic baselines
analysis/         dataset metrics and critic diagnostics
experiments/      per-run CLI argument files for all paper experiments
slurm/            SLURM templates used on the cluster
scripts/          dataset download from HuggingFace
```
