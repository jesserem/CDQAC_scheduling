# CDQAC — Conservative Discrete Quantile Actor-Critic for Scheduling

Official implementation of

> **Generalizing Beyond Suboptimality: Offline Reinforcement Learning Learns Effective Scheduling through Random Solutions**
> Jesse van Remmerden, Zaharah Bukhsh, Yingqian Zhang
> *Transactions on Machine Learning Research (TMLR), 2026*
> OpenReview: https://openreview.net/forum?id=4vVhm4817Q

CDQAC is an offline reinforcement learning method for the Job Shop Scheduling
Problem (JSP) and the Flexible Job Shop Scheduling Problem (FJSP). It learns
scheduling policies purely from static, suboptimal datasets — including data
generated by a random policy — and matches or outperforms strong
online RL baselines without any environment interaction during training.


## Installation

```bash
conda create -n cdqac python=3.11
conda activate cdqac
pip install -r requirements.txt
```

For a CUDA build of PyTorch, see the note in `requirements.txt`.

## Datasets

The packed training/evaluation datasets (and pretrained checkpoints) are
hosted on the HuggingFace Hub and are downloaded with `download_datasets.py`
from the repository root:

```bash
python download_datasets.py                    # training datasets only
python download_datasets.py eval               # + evaluation datasets
python download_datasets.py eval checkpoints   # + pretrained checkpoints
```

Training datasets are placed under `train_dataset/fjsp` and
`train_dataset/jsp` (the locations expected by the default configs), e.g.
`train_10_5.npy` / `val_10_5.npy` for 10×5 instances. Each `.npy` training
file holds one dict per instance with the instance definition (`JobLength`,
`OpPT`) and the trajectories of every data source: PDR rules (`rules`), GA
hall-of-fame/population (`ga`, `ga_pop`), random rollouts (`random`), and
ε-PDR rollouts (`eps_random_*`), stored as action lists that are replayed
through the environment at training time.

All datasets can also be regenerated from scratch:

```bash
# 1. Generate instances + PDR trajectories for all sizes/sources
python -m data_generation.generate_datasets

# 2. Append random trajectories
python -m data_generation.add_random_trajectories --path_file ./train_dataset/fjsp/train_10_5.npy --num_random 100

# 3. (Optional) epsilon-PDR trajectories (App. F.3)
python -m data_generation.add_eps_pdr_rules --path_file ./train_dataset/fjsp/train_10_5.npy --eps_random 0.1

# 4. (Optional) GA trajectories: run data_generation/run_GA_custom.py inside a
#    clone of the Job Shop Scheduling Benchmark repo (see the file's docstring),
#    then merge the resulting JSONs:
python -m data_generation.add_ga_data --dataset ./train_dataset/fjsp/train_10_5.npy --ga_folder ./GA_data/10_5
```

## Training

`train.py` is the single training entry point for CDQAC and all baselines.
The method is selected with `--method`; every other argument is forwarded to
that method's configuration (see [Configuration](#configuration)):

```bash
# CDQAC on the 10x5 FJSP Random dataset (the paper's default setting)
python train.py

# Other sizes / problem classes
python train.py --train_instance train_15_10.npy --eval_instance val_15_10.npy --seed 2
python train.py --data_path ./train_dataset/jsp --train_instance train_10_5.npy --eval_instance val_10_5.npy

# Baselines
python train.py --method iql --q_lr 1e-4
python train.py --method td3_awr
```

| `--method` | Algorithm |
|---|---|
| `cdqac` (default) | CDQAC (ours) |
| `bc` | Behavioral Cloning |
| `iql` | Implicit Q-Learning |
| `dmsac` | Offline-LD (discrete maskable SAC) |
| `mqrdqn` | Offline-LD (maskable QR-DQN) |
| `td3_awr` | TD3-AWR |

Dataset sources are selected with `--use_dispatching` (PDR), `--use_ga_hof` /
`--use_ga_pop` (GA), `--use_random` (default), and `--use_eps_pdr`; any
combination can be enabled. Checkpoints and a `config.yml` are written to
`--save_folder` (default: `checkpoints/`).

Ablations (Sect. 5.5) are switches on the CDQAC config: `--use_cql False`,
`--use_qrdqn False`, `--use_adv_net False`, `--update_freq_policy 1`, and the
dataset-property ablations `--use_proxy_reward`, `--use_sparse_reward`,
`--cutt_off_episode_prob 0.1` (Table 3).

Every method supports `--use_disk_buffer true`, which stores transitions in
memory-mapped files on disk and prepares batches with DataLoader workers, so
dataset size is bounded by disk instead of RAM (tuning knobs are documented in
`cdqac/buffer/disk_buffer.py`).

Weights & Biases logging is optional: add `--use_wandb True` (requires
`wandb` to be installed and configured).

## Configuration

All hyperparameters live in per-method dataclasses in
[`cdqac/configs/`](cdqac/configs/):

| File | Method |
|---|---|
| `cdqac_config.py` | CDQAC — defaults reproduce Table 11 of the paper |
| `bc_config.py` | Behavioral Cloning |
| `iql_config.py` | Implicit Q-Learning |
| `d_msac_config.py` | Offline-LD (discrete maskable SAC) |
| `mqrdqn_config.py` | Offline-LD (maskable QR-DQN) |
| `td3_awr_config.py` | TD3-AWR |

Each file defines a `TrainConfig` dataclass whose fields are grouped into
data selection, network architecture (DAN encoder + critic), algorithmic
switches, optimization, and evaluation/logging. Any field can be overridden
on the command line via [pyrallis](https://github.com/eladrich/pyrallis),
e.g. `python train.py --method cdqac --cql_alpha_offline 0.1 --batch_size 512`.
The resolved configuration of every run is saved next to its checkpoints as
`config.yml`.

## Evaluation

`eval_model.py` evaluates any checkpoint produced by `train.py` (the network
type is inferred from the run's `config.yml`, or from the state dict itself
for bare `.pt` files) on a folder of FJSP (`.fjs`) or JSP (`.jsp`) instances:

```bash
# Greedy (deterministic) evaluation on generated 10x5 FJSP instances
python eval_model.py checkpoints/<run_folder> --eval_folder ./data/SD1/10x5

# 100-sample evaluation (best of 100 sampled solutions, as in the paper)
python eval_model.py checkpoints/<run_folder> --eval_folder ./data/BenchData/Brandimarte --num_samples 100

# Pretrained checkpoint (downloaded with `python download_datasets.py checkpoints`)
python eval_model.py checkpoints/fjsp/cdqac/cdqac_random_10_5.pt --eval_folder ./data/SD1/10x5
```

`<checkpoint>` is either a run folder (containing `config.yml` and
`best_det_offline.pt`) or a `.pt` file. With `--num_samples 1` (default) the
policy acts greedily; with `--num_samples N` the best of `N` sampled
solutions is kept. Results are written as a CSV (`name, makespan, runtime`)
to `--save_path` (default: `./results`).

Evaluation instance sets under `data/`:

- `data/SD1`, `data/SD2` — generated FJSP instances (10×5 up to 40×10)
- `data/BenchData` — Brandimarte and Hurink (edata/rdata/vdata) FJSP benchmarks
- `data/JSP` — Taillard (TA), Demirkol (DMU), and Lawrence (LA) JSP benchmarks

Reference points and baselines:

```bash
python -m evaluation.eval_dispatching       # PDR baselines (FJSP)
python -m evaluation.eval_dispatching_jsp   # PDR baselines (JSP)
python -m evaluation.eval_random            # random policy baseline
python -m evaluation.ortools_solver         # CP-SAT (OR-Tools) reference solutions
python -m evaluation.summarize_gaps         # aggregate result folders into per-experiment tables
```

## Analysis (Sect. 5.2, App. F & K)

`analysis/` contains the scripts behind the dataset-property study and the
critic diagnostics; each is documented in its header and takes a trained
checkpoint / dataset path as argument:

- `coverage_action_prefix.py` — state–action coverage (SACo, Table 2)
- `trajectory_quality_return.py` — trajectory quality (TQ, Table 2)
- `density_embedding_knn.py` — embedding-space k-NN density proxy (Table 2)
- `quantile_distribution_experiment.py`, `critic_diagnostics.py`,
  `cql_effect_experiment.py` — quantile critic diagnostics (App. K)
- `notebooks/` — notebooks used to produce the tables and figures
